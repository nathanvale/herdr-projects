# Domain docs

This repository uses a single-context layout.

Before exploration, read the root [GLOSSARY.md](../../GLOSSARY.md) and
relevant decisions under [docs/adr/](../adr/). If optional domain
documents are absent, proceed without creating placeholders.

Use glossary terms consistently in proposals, issues, code and tests.
Identify missing concepts when they matter to the work.

Explicitly surface conflicts with existing ADRs before proposing
a different decision.
