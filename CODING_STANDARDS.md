# Coding standards

## Verification

- Follow [AGENTS.md](AGENTS.md) for local verification and runtime boundaries.
- Write meaningful regressions across the public or process interface. Complete the owning test-design brief before changing tests or harnesses.
- Distinguish source inspection, authored tests, executed checks, CI results and native qualification. Fixture evidence does not prove native behavior.
- Keep source-checkpoint validation separate from candidate readiness. Preserve every pending port and regression obligation in the [migration inventory](docs/migration/upstream-v3.1.3.json).

## Ownership and admission

- Put provider-specific interpretation behind the native forge interface. Keep local Git, approval, task state and cleanup with their existing owners.
- Preserve repository-qualified identities and the GitHub meaning of legacy unqualified records. Revalidate exact candidate, source and destination before effects.
- Keep incomplete, missing, pending, failed and passed checks distinguishable.
- Persist an exact operation claim before uncertain dispatch. Reconcile that identity; empty inventory and error text do not prove non-submission.
- Fence old application senders before recovery. State each guard's scope; application serialization does not establish core receipts or idempotency.
- Preflight provider and process admission before disrupting existing work. Preserve admitted binding through asynchronous preparation and final dispatch.

## Credentials, settings and recovery

- Keep credential values outside settings, argv, labels, persisted environment overrides and launch records. Use the admitted execution-host credential owner.
- Preserve human ownership of provider connection controls. Presence checks and deployment inventory do not attest an account or inference access.
- Preserve scope identities, inheritance, explicit empty values and Reset. Reject stale or invalid edits before replacing saved selections.
- Preserve Personal pass-through defaults and recorded conversation bindings. New-start defaults cannot silently reroute existing conversations.
- Use native recovery where qualified; port demonstrated superior guarantees. Keep one revival/admission owner and distinguish fresh sessions from resume.
- Isolate plugin failures. Legacy compatibility and last-good behavior remain required qualification, not claims made by importing upstream source.

## Migration proof owners

The [repository-binding contract](docs/migration/upstream-v3.1.3.md) names native owners, fixed F/P proof sources and held decisions. [Check](.github/workflows/check.yml) owns native CI and the blocking candidate-readiness job.
