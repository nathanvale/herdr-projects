    What this review found
    • Fixed: changing a saved choice away and back must still invalidate old selectors. The implementation now persists a monotonically increasing selection revision.
    • Guarded: saving does not start work or release holds. Existing conversations remain locked. A lost start reply retains its launch identity and blocks blind retry.
    • Open: a crash after recording a launch but before submitting it can leave an unconfirmed record with no process. Refusing retry prevents duplicates but does not restore progress.
    • Open: the new-task path currently prepares its worktree and can start its coordinator before validating the worker route. Admission should move before these side effects.
    • Open: an admitted restart plan lives only in memory. A crash after the old process stops can lose that plan. The new-start selector does not enable changing existing conversations.
    Scope: one application owner, one task, two example deployments. Real authentication, provider compatibility, parent identity, task dependency scheduling, terminal reconciliation and filesystem recovery are not implemented here. No credentials, network, local storage or model requests are used.
    Source: server/core/agents.ts selectionToken, saveSelection, preflight, launch; server/core/tasks.ts launchNow; server/core/pilot-lifecycle.ts regularRestart. Reference implementation: 1f4dc1e. Findings distinguish a source-inspected ordering gap from a modelled crash window.
